## 1. 人话摘要（200 字内）

S7 要让图、表、公式等视觉解析产物成为可定位、可召回、可校验的 Evidence，而不是把 VLM 写的描述直接当事实。现状：视觉解析链确实产出过 8 条图记录（page + figure_id + description 三样是真的），但它们没有 bbox、没有独立 caption、没有逐图图片文件，进 evidence.db 时全部被判 degraded，后来还被新版本挤成了历史记录；检索、上下文、验证三段都只看得见文本。修完用户能看到：问"Figure 1 左边是什么"时，系统真的召回那条图记录、带回同页正文，并且只有真实视觉证据才能支撑视觉声明——没有 bbox 就诚实说到页和图，不编。

| **figure（结构化）** | ⚠️ 部分 | figure_id（`doc:pN:fM`）+ figure_index 是结构化的；但"Figure 1"这种**图编号只出现在 description 散文里**，无独立字段 |

## 3. 修改后图（T2 目标：新增控制点与失败出口）

以下为**目标，不是现状**（V3 §14 S7-T2 七项；详单见第 8 节）：

```text
视觉问题（如 "Which figure shows training loss convergence?"）
   │
   ▼
 [检索层 双 lane] text lane（现状不动）
   │            + visual lane【新增】：BM25/dense over 02 description
   │              (Candidate{evidence_id, modality, score})
   ▼
 [C1 融合排名 + modality quota【新增控制点】]
   │  保证 top-K/预算内 visual 证据有最低名额，不被文本挤没
   ├─ quota 未满足 → 显式记录 shortfall，不静默            【失败出口 1】
   ▼
 [C2 visual-to-text page 桥接【新增控制点】]
   │  figure(page=N) → 同页/邻页 text chunks（caption 常在同页正文里）
   │  (EvidenceItem{modality="text", neighbor_of=<figure evidence_id>})
   ▼
 [context.assemble → answer.draft → answer.verify（S6 链复用）]
   ▼
 [C3 Visual Fact Gate【新增控制点】]
   │  visual claim 只计满足全部条件的 support：
   │  modality=visual ∧ 非 degraded ∧ 当前有效 ∧ 可定位（page+figure_id）
   ├─ 只有文本提到图 → 不算 visual support → unsupported    【失败出口 2】
   ├─ 无任何真实 visual evidence → abstain / human_review   【失败出口 3】
   ▼
 [C4 真实评测【新增】]
   │  5~10 个人工冻结真实 visual gold case，与 synthetic fixture 分开报告
   ├─ 无 bbox → region_recall_at_k 保持 deferred，
   │    只报 page/figure-level Recall@K 与 ViR               【失败出口 4：不虚构 bbox】
   ▼
 对比文本单路 / 视觉单路 / 融合：Visual Recall@K、ViR、错引率、延迟
```

四个控制点的共同原则：视觉证据的"事实性"来自**可定位的真实记录**（page+figure_id，有 bbox 时到 region），VLM description 只是它的 supporting 级文本代理——像素才是 primary，而像素现在只能通过 artifact_uri 回到 PDF 页。

## 4. 固定案例：VE-EVAL01 逐步 I/O

选用 `benchmarks/visual_cases.jsonl` 的 **VE-EVAL01**（frozen eval fixture，synthetic；真实 gold case 是 T2 第 1 项要人工冻结的，本讲义不伪造）：

```json
{"case_id": "VE-EVAL01", "kind": "eval_fixture",
 "question": "Which figure shows training loss convergence?",
 "gold_figure_ids": ["abc123def4567890:p3:f0"],
 "ranked_candidates": ["abc123def4567890:p4:f0",
                       "abc123def4567890:p3:f0",
                       "abc123def4567890:p9:f0"],
 "expect_recall_at_1": 0.0, "expect_recall_at_3": 1.0}
```

**现状链逐步（诚实版——走不通）**：

1. **evidence.search**。输入 `{query: "Which figure shows training loss convergence?"}` → hybrid 两 lane 都建在 `load_text_evidence(modality="text")` 上（hybrid_search.py:48、bm25.py:18）→ 输出只有文本 chunk 的 Candidate。三条 gold 图记录**在索引里不存在**，召回无从谈起。
2. **filters**。即使把 visual 记录手工塞进候选，`exclude_degraded=True`（filters.py:23,31-32）也会以 `degraded: missing_region_bbox` 全部丢弃并留下 filter_reasons——丢得明白，但还是没了。
3. **context.assemble**。selector 按 composite score 贪心填充，无 modality 维度（selector.py:106-157）；邻居扩展对 visual 记录是空操作（无 chunk_id）。
4. **answer.verify**。若 draft 说 "the figure on page 3 shows loss converging near 1.2"，claims.py:124-127 把它分类为 `ClaimType.VISUAL`，然后就没有然后了——claim_map.py:116-126 拿它跟**文本证据**算 token overlap，文本里提到 "loss curve converges" 就能"支持"这条视觉声明。视觉声明被文本证据盖章，这正是 Visual Fact Gate 要堵的洞。
5. **离线评分（唯一现状能跑的一步）**。`visual_eval.recall_at_k(ranked, gold, k)`（visual_eval.py:25-29）：recall@1 = |{p4:f0} ∩ {p3:f0}| / 1 = **0.0**；recall@3 = **1.0**——与冻结期望精确一致（tests/verification/test_visual_eval.py 冻结）。`run_visual_eval` 真实入口在缺 KB/结果/gold 任一输入时返回 `status="deferred"` 并明说"绝不编数字"（visual_eval.py:110-131）。

**目标链逐步（T2 后应呈现的形状）**：

1. **visual lane 召回**。输入 question → 在 description 语料上检索 → 输出 `[{evidence_id: <p4:f0 的 ev>, modality: "visual", score: ...}, {<p3:f0>}, ...]`。对应到真实 baseline，就是 `ev-c4b96cd872bccd67e1da5579`（p3, Figure 1, description 以 "**Subject:** The Transformer - model architecture" 开头）这种记录能被问题命中。
2. **C1 modality quota**。融合排名时 visual 候选至少保留名额（如 top-10 内 ≥2 或 evidence token 预算的 ≥15%）→ 输出仍含 p3:f0；若 visual lane 本身召回不足，quota 记 shortfall 而不是用文本填满假装没事。
3. **C2 page 桥接**。命中 `<p3:f0>` → 查同 document、page=3（必要时 ±1 页）的 text chunks → 带回含 "Figure 1" 字样的 caption/正文 chunk，标 `neighbor_of=<visual evidence_id>`——形状与现有 `expand_neighbors` 的 note 一致（quota.py:127），但键从 chunk_id 算术换成 page 匹配。
4. **C3 Visual Fact Gate**。draft 的视觉声明逐条对账：绑定的 evidence 必须 `modality=="visual"` 且非 degraded 且当前有效且 page+figure_id 齐全；VE-EVAL01 场景里 p3:f0 记录满足 → supported；若系统只找到文本 chunk 说 "loss converges near 1.2" → 该 visual claim 判 unsupported。
5. **C4 评测**。真实 gold case 的 ViR/Recall@K 与 VE-EVAL01 这类 synthetic fixture **分开两行报告**（V3 §14 阶段门："真实 ViR 与 fixture 指标分开"）；region_recall_at_k 因无真实 bbox 继续 deferred（visual_eval.py:110-131 的诚实出口原样保留）。

## 6. 关键代码位置（5 处）

**① `app/utils/vp_figure_describer.py:199-218` — figure_rows 组装与写出**
输入：`descriptions_by_page`（(pdf, page) → VLM description 列表）；输出：02_visuals_kb.jsonl 行，六字段 `{source, page, document_id, figure_index, figure_id, description}`，`figure_id=f"{doc}:p{page}:f{idx}"`；副作用：追加写 JSONL；失败行为：VLM 异常按页 log 后 `continue`（:184-188）——**该页静默无任何视觉记录**（m0-20260922 运行 15 页全失败 → 02 文件根本不生成）；重要性：视觉证据的出生点，这六字段就是下游全部可用信息——没有 bbox 和 caption 不是 adapter 弄丢的，是这里从未产生。

**② `app/evidence/adapter.py:270-315` — visual row → Evidence**

**③ `app/evidence/store.py:262-315`（query_evidence）+ `app/retrieval/bm25.py:18-41`（load_text_evidence）+ `app/evidence/hybrid_search.py:48` — 检索供给链**

**④ `app/context/quota.py:86-128`（expand_neighbors）+ `app/context/selector.py:106-157`（select_evidence） — 邻居与配额**

## 7. 术语表（8 个）

1. **modality（模态）**：Evidence 的类别标签，三值 text/visual/metadata（models.py:26-29）。检索索引、过滤器、selector 都看得见这个字段，但现状只有 text 被真正使用。
2. **degraded（降级）**：证据缺关键定位信息时的诚实标记（models.py:113-114）。degraded 记录默认被查询、索引、绑定三重排除（store.py:295-296、bm25.py:54、claim_map.py:119-120），显式要求才可见。8 条 visual 的 degraded_reason 都是 `missing_region_bbox`。
3. **figure_id**：图记录的结构化定位符，格式 `{document_id}:p{page}:f{index}`（vp_figure_describer.py:209；visual_qa.py:34 有校验正则）。现状 visual 证据最细的定位粒度——到页内的第几条 VLM 记录，**不是**论文里的 "Figure 1" 编号。
4. **region_bbox**：图在页内的矩形区域 `{x0,y0,x1,y1,unit}`（models.py:77-82）。当前解析链从不产生它；有它才有 region-level 定位与 IoU 评测，没有就必须诚实停在 page/figure-level。
5. **text-to-visual recall**：用文本问题找回视觉证据的检索方向——问题 vs description 语料。现状断在索引 text-only（hybrid_search.py:48）。
6. **visual-to-text neighbor expansion**：命中图记录后带回相邻文本（caption、正文）的方向。现有实现只会 chunk_id 算术（quota.py:76-83），T2 需要 page 桥接。
7. **Visual Fact Gate**：验证侧控制点——visual claim 的支持只能来自真实 visual evidence（modality=visual、非 degraded、当前有效、可定位），文本里"提到图"不算数。VLM description 是 supporting 级代理，不是视觉事实本身。
8. **ViR（Visual-grounded Recall，视觉事实召回）**：被召回的 gold 视觉事实 ÷ gold 视觉事实总数（docs/EVAL_HARNESS.md:71）。回答"需要图才能答的问题，系统真把那条图证据找回来了吗"。仓库内只有 synthetic fixture 指标（docs/BASELINE.md:55 标"零实现"真实口径）；论文的 ViR 数字是上游 A 类资产，永不可引用为本项目成绩。

## 9. 三件必须记住的事

1. **真实产物里视觉证据只有 page + figure_id + description 三样是真的**；bbox、caption 字段、逐图图片文件都不存在（§2 逐项实证）。8 条 visual 记录全 degraded（missing_region_bbox）且已全部被 supersede——**当前有效 visual = 0**。任何 "region-level" 表述在这个仓库里都是虚构。
2. **VLM 描述是 supporting 级文本代理，不是视觉事实**。Visual Fact Gate 的含义：只有 modality=visual、非 degraded、当前有效、可定位的证据才能支撑视觉声明；正文里提到 "Figure 1 shows..." 不算 visual support——没有这道门，视觉问题就是用文本蒙的。
3. **检索、邻居、配额三处都是 text-only 结构**：索引默认 `modality="text"`（bm25.py:18）、邻居只会 chunk_id 算术（quota.py:76-83）、配额只有 per-page/per-doc 没有 modality 维度（selector.py:106-157）。S7-T2 的第 3、4 项改动就落在这三个坐标上。

## 10. 自测题（折叠答案）

**Q1（数据流）**：用户问 "Figure 1 的左半边是什么？"——在现状链上这个问题走到哪里、以什么形状结束？在 S7 目标链上，ev-c4b96cd872bccd67e1da5579（p3, Figure 1）要经过哪些控制点才能支撑回答？

<details><summary>答案</summary>
现状：evidence.search 的 hybrid 索引只装 text（hybrid_search.py:48），图记录在索引里不存在；检索只能返回 p3 的文本 chunks（其中恰好有 "shown in the left and right halves of Figure 1" 字样）；answer.verify 把 "the left half of Figure 1 is the encoder" 分类为 VISUAL claim（claims.py:126），然后用文本 chunk 的 token overlap 判 supported——**视觉声明被文本证据盖章通过**，回答看似正确但从未见过图。目标链：① visual lane 用问题命中该记录的 description（"left encoder half"）→ ② C1 modality quota 保证它不被 357 条历史/119 条当前文本挤出 top-K → ③ C2 page 桥接带回 p3 文本 chunks（neighbor_of 标注）→ ④ C3 Visual Fact Gate 检查 modality=visual ∧ 非 degraded ∧ 当前有效 ∧ page+figure_id 齐全——注意该记录现状 degraded 且已 supersede，所以 T2 第 2 项必须先产出非降级的有效版本，否则 Gate 诚实判 unsupported 而不是放水。
</details>

**Q2（设计取舍）**：modality quota 为什么不能只用"把 visual lane 的 top_k 调大"来替代？（必答点 3）

<details><summary>答案</summary>
top_k 管的是"visual lane 内部取多少"，管不了"融合后 visual 占多少"。挤掉路径在融合与预算两段：融合排名按 score 排序，description 的词汇与问题的重合度通常低于正文 chunk（正文和问题共享术语，description 是 VLM 的另一套措辞），visual 候选在 merged list 里天然排尾，top_k 截断后全灭；过了融合还有 context 阶段——select_evidence 按 composite score 贪心填充，visual 记录的 authority_level 是 "supporting"，不在 AUTHORITY_WEIGHTS 表里（selector.py:31-36），吃 DEFAULT_AUTHORITY_WEIGHT=0.5，比文本的 primary=1.0 低一半，预算竞争再输一轮。top_k 调得再大，两段 text-biased 排序照样把 visual 磨没。quota 是把"视觉证据最低在场量"变成显式约束（融合名额或预算占比），并在不满足时记 shortfall——这是结构性保证，不是参数祈祷。
</details>

**Q3（失败后果）**：如果 S7-T2 做了 visual lane 和配额、却跳过 Visual Fact Gate，直接把 VLM description 当作可支撑视觉声明的证据接进 verifier，会出现什么？（必答点 4）

<details><summary>答案</summary>
"召回了，但更敢错了"：视觉问题现在能命中 description，verifier 也照常判 supported——但 description 本身是 VLM 对像素的一次性解读，会幻觉（visual_qa.py 的 low_information/wrong_page 缺陷类就是为承认这点存在的；真实记录里的 "Discrepancy Check" 段甚至显示 VLM 在对账 Nx 与 N=6），而且没有 bbox，任何"图的某区域显示 X"的断言都无法回溯到像素。Gate 缺失时，一条幻觉 description 会以 full confidence 通过验证出网，比现状（诚实地说没有视觉证据、fallback 到文本）更危险——因为系统现在"看起来有视觉能力"，错引率上升而无人察觉。阶段门"没有虚构 bbox""真实 ViR 与 fixture 分开"正是防这种半截工程：Gate 强制 support 只能来自真实、有效、可定位的 visual 记录，描述与像素之间的信任差由 degraded/supporting 语义显式承载。
</details>

## 11. 面试表达

**60 秒口述**："这个阶段解决'图不能白解析'的问题。我先做了一件最基础但最常跳过的功课：打开真实 parser 产物逐字段核对——结论是三样真、三样假：页码、图 ID、VLM 描述是真的，bbox、独立 caption、逐图图片文件都不存在，所以库里 8 条图记录全部因缺 bbox 被诚实降级，而且已被新版本挤成历史。基于这个事实，设计是四个控制点：检索加一条视觉 lane 让文本问题能召回图描述；融合和上下文加 modality 配额，因为相关度排序和权威级权重天然偏向文本，没有配额视觉证据结构性出不了场；命中图之后按页桥接带回同页正文和 caption；最后也是最重要的——Visual Fact Gate：视觉声明只能被真实、有效、可定位的视觉证据支撑，VLM 写的描述只是 supporting 级代理，正文里提到图不算数。评测用 ViR——视觉事实召回——和 HR、引用精确率分开报告，真实 gold 和合成 fixture 分开报告，没有 bbox 就诚实做到页和图一级，region 级指标保持 deferred，绝不虚构坐标。"

**可以说**：真实 parser artifact 的逐项字段判定（§2 表格，全部有文件实证）；8 条 visual 记录全 degraded=missing_region_bbox 且已 superseded、当前有效 visual=0 的事实；视觉解析链五段结构与其六字段输出（vp_figure_describer.py:199-218）；检索 text-only 的三个默认参数坐标（bm25.py:18、hybrid_search.py:48、store.py:295-296）；邻居扩展只会 chunk_id 算术、selector 无 modality 维度的现状；ClaimType.VISUAL 有分类无 Gate 的缺口（claims.py:124-127 vs claim_map.py:116-126）；visual_qa/visual_eval 作为 M7 离线 scaffold 的存在与 deferred 诚实出口（visual_eval.py:110-131）；synthetic fixture 指标（VE-EVAL01 recall@1=0.0/recall@3=1.0）的存在。

**暂时不能说**：系统已能召回视觉证据（visual lane 不存在）；已有真实 ViR 数字（只有 synthetic fixture，真实 gold 是 T2 第 1 项）；视觉证据已接入生产问答链（T2 第 6 项未做）；有任何 region-level 能力（无真实 bbox，region_recall 必须 deferred）；Visual Fact Gate 已实现（T2 第 5 项）；论文的 ViR 数字（A 类上游资产，docs/BASELINE.md:55、docs/OWNERSHIP.md:48，永不可引用为本项目成绩）。
